# Estado real de la base

Esta entrega conserva el código del prototipo como punto de partida, con documentación nueva basada en la definición. No es una implementación terminada de todo el producto. Fecha: 13 de noviembre de 2026.

Actualización: 16 de noviembre de 2026. Se conserva yt-dlp para búsqueda y RapidAPI prepara el MP3 del resultado elegido. El frontend ya no permite escoger proveedor. La API llama por HTTPS al endpoint RapidAPI y requiere `RAPIDAPI_KEY` y `RAPIDAPI_USERNAME` solo en backend. Se quitaron la mecánica, selector y configuración activa de Apify. La integración RapidAPI/Firebase no se ha ejecutado con servicios reales ni se ha consumido cuota. `web/index.html` apunta a `https://cuadro-sonoro.onrender.com`; la web se sirve aparte. Para desarrollo local o una API en Raspberry Pi, cambia el meta a la dirección de esa API. Procedimiento en [PRUEBA_RAPIDAPI.md](PRUEBA_RAPIDAPI.md).

Los límites de 15 minutos, 40 MiB y la carátula 320×320 son valores del prototipo, no decisiones definitivas de producto. No confundir flags de configuración de `/health` con permisos verificados. Las URLs de medios son legibles por cualquiera que las conozca; la ruta SHA-256 separa registros, no sirve de autorización. Las reglas actuales fueron aplicadas manualmente a Firebase real; no se utilizó Firebase CLI.

La conexión local al proyecto Firebase real y el identificador anterior del cuadro están en archivos ignorados por Git. Las reglas aplicadas manualmente permiten lectura directa de slots y medios por URL conocida; bloquean listados y escrituras públicas. El 12 de noviembre de 2026 se importó «Carefree» de Kevin MacLeod desde una búsqueda real de YouTube con Docker local. El MP3 y la portada se publicaron en Storage y se verificaron en RTDB público y API; después Carlos pidió borrarlos y se retiraron la selección, el audio y la imagen. Chrome Headless reprodujo el MP3 y avanzó sin errores antes de la eliminación; no se comprobó escucha humana. Una importación anterior con yt-dlp desde Render falló con HTTP 429/403 durante `source_lookup`; el endpoint `/search` independiente con yt-dlp y la descarga RapidAPI aún están pendientes de validación real. Resultados en [VALIDACION.md](VALIDACION.md).

Consultar [validaciones](VALIDACION.md), [plan](PLAN.md) y [definición](DEFINICION.md). El diagnóstico histórico de Render confirmó HTTP 429/403 de YouTube; no predice el comportamiento de yt-dlp en una Raspberry Pi/red doméstica. La web versionada usa Render; para API local o Raspberry Pi se debe cambiar el meta y preparar CORS. No desplegar el prototipo como producto listo: faltan validación real de RapidAPI, firmware/hardware e integración QR/NFC.


## Sustitución del proveedor de descarga (16 de noviembre de 2026)

Por instrucción de Carlos, se elimina la integración activa Apify y se sustituye por RapidAPI YouTube MP3. La búsqueda yt-dlp permanece; RapidAPI recibe el ID seleccionado y devuelve un enlace MP3 que se descarga en el backend. `RAPIDAPI_KEY` queda como secreto backend; `RAPIDAPI_USERNAME` se usa para generar el encabezado de identificación del host multimedia. La variante no se ha probado con una conversión real; una llamada puede consumir cuota. El MCP de Codex no es runtime del backend y no se usa desde la aplicación. Véase [PRUEBA_RAPIDAPI.md](PRUEBA_RAPIDAPI.md).
