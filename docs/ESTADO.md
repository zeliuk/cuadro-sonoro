# Estado real de la base

Esta entrega conserva el código del prototipo como punto de partida, con documentación nueva basada en la definición. No es una implementación terminada de todo el producto. Fecha: 13 de noviembre de 2026.

Actualización: 16 de noviembre de 2026. En el formulario web se puede elegir Apify o yt-dlp para cada descarga; yt-dlp es la opción inicial y la API conserva `apify` como valor predeterminado para solicitudes antiguas sin campo `provider`. La tarea persiste el proveedor para recuperaciones y reintentos. La ruta yt-dlp descarga y convierte en el host de la API; ambas rutas comparten validación, medios y publicación. `web/index.html` apunta a `http://127.0.0.1:8000`, la API local del mismo equipo. Para ejecutar yt-dlp en una Raspberry Pi desde el móvil, el HTML servido debe apuntar a la dirección LAN de la API en la Pi. La ruta local yt-dlp aún no se ha probado con YouTube/Firebase reales; los procedimientos están en [PRUEBA_YTDLP_LOCAL.md](PRUEBA_YTDLP_LOCAL.md) y [PRUEBA_APIFY_RENDER.md](PRUEBA_APIFY_RENDER.md).

Los límites de 15 minutos, 40 MiB y la carátula 320×320 son valores del prototipo, no decisiones definitivas de producto. No confundir flags de configuración de `/health` con permisos verificados. Las URLs de medios son legibles por cualquiera que las conozca; la ruta SHA-256 separa registros, no sirve de autorización. Las reglas actuales fueron aplicadas manualmente a Firebase real; no se utilizó Firebase CLI.

La conexión local al proyecto Firebase real y el identificador anterior del cuadro están en archivos ignorados por Git. Las reglas aplicadas manualmente permiten lectura directa de slots y medios por URL conocida; bloquean listados y escrituras públicas. El 12 de noviembre de 2026 se importó «Carefree» de Kevin MacLeod desde una búsqueda real de YouTube con Docker local. El MP3 y la portada se publicaron en Storage y se verificaron en RTDB público y API; después Carlos pidió borrarlos y se retiraron la selección, el audio y la imagen. Chrome Headless reprodujo el MP3 y avanzó sin errores antes de la eliminación; no se comprobó escucha humana. Una importación anterior con yt-dlp desde Render falló con HTTP 429/403 durante `source_lookup`; el endpoint `/search` independiente con yt-dlp y la descarga Apify aún están pendientes de validación real. Resultados en [VALIDACION.md](VALIDACION.md).

Consultar [validaciones](VALIDACION.md), [plan](PLAN.md) y [definición](DEFINICION.md). El diagnóstico histórico de Render confirmó HTTP 429/403 de YouTube; no predice el comportamiento de yt-dlp en una Raspberry Pi/red doméstica. La web ahora usa API local; para Pi/móvil se requiere configurar su dirección LAN en el HTML servido y preparar acceso/CORS. No desplegar el prototipo como producto listo: falta elegir una API alcanzable desde móvil, además de firmware/hardware e integración QR/NFC.


## Integración Apify (16 de noviembre de 2026)

Implementado localmente, pendiente de validación real: `APIFY_TOKEN` solo en backend; Actors configurables por entorno; búsqueda de candidatos con yt-dlp, sin credencial ni coste de Actor; adaptadores de descarga para `lurkapi/youtube-to-mp3-audio-downloader` y `johnvc/youtube-download-api`; estado de run persistido y recuperable; respuesta ambigua de creación se bloquea sin POST de repetición; resultado individual revisado; transferencia autenticada a key-value stores de Apify, limitada y validada por ffprobe; cancelación remota con marca durable; timeout remoto predeterminado de 600 s; concurrencia y frecuencia globales; CORS de preflight Authorization. El token solo se envía a `api.apify.com` como cabecera, nunca a otros hosts ni en URL. Pruebas manuales de johnvc desde Apify Console: un vídeo público falló `YOUTUBE_BLOCKED` con 0 archivos y `$0.000020` reportados; otro obtuvo un MP3 de 2.7 MB en 5 intentos con `$0.000064` total. Un run posterior fue terminado por timeout de 240 s antes de completar. Esto muestra que puede funcionar por algunas rutas, pero no garantiza la descarga; el adaptador del backend y el flujo completo Render/Firebase siguen sin validar. Los logs de resultado fallido exponen solo indicadores redactados de estado/campos, no el error bruto del Actor. La prueba Apify/Render y sus límites están en [PRUEBA_APIFY_RENDER.md](PRUEBA_APIFY_RENDER.md).
